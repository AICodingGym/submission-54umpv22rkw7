# 主助手归纳评分标准 → Qwen3-4B 执行评分

持续目标：由主助手系统阅读和归纳全部固定 train 划分的 10,905 篇作文与标签，
形成有样本依据的评分标准，在冻结 Qwen3-4B 上评估并迭代到较好的成绩。
操作目标暂以接近同一选择集 DeBERTa B1 QWK 0.80 为准，同时检查 MAE，
不能只凭选择集一次偶然提升宣布完成。用户未指定硬阈值；此数值是工作目标。

`protocol.json` 是进度的权威记录；此页面摘要需随进度更新。

## 阅读与证据

`review_manifest.csv` 覆盖所有且仅有 train 作文，含原文哈希，固定成 606 批，
每批最多 18 篇。按分数交错便于跨档比较；高分样本较少，后续批次分布会变化。
原文保持不变。每批分三次输出，每次至多六篇，避免工具输出截断：

```bash
../.venv/bin/python rubric_research/review.py --batch 11 --section 1
../.venv/bin/python rubric_research/review.py --batch 11 --section 2
../.venv/bin/python rubric_research/review.py --batch 11 --section 3
```

只有实际读完所有原文后，才在 `notes/XXXX.md` 逐篇记录观察并更新
`protocol.json` 的 completed_batches、semantic_read_rows 和 next_batch。
输出截断必须补读，不得靠脚本统计、弱模型摘要或仅检查文件存在冒充主助手阅读。

`review.py` 无参数核验：划分隔离、原文哈希、标签、逐篇笔记是否存在及进度计数。
它验证阅读记录的一致性，不证明阅读行为本身。

## 后续执行规则

1. 完成全训练集证据归纳，持续检验边界例外，不机械累积规则。
2. 主助手负责提示词和评分程序的修订，Qwen3-4B 不再自行反思改写。
3. 固定权重、推理参数与开发样本；比较直接评分、概率期望、必要的推理流程。
4. 用训练误差提供修改依据，用选择集检验收益；保留所有尝试，记录多次选择偏差。
5. 标准冻结后才拟合新的 calibration 阈值，不把旧校准结果偷偷带入提示词修订。
6. 最终验证集在所有候选冻结后统一评价，平台分数不作为反复调参信号。
7. 得分不足时继续根据证据修订，不把另训模型或直接融合 DeBERTa 冒充本路线成功。

## 初步发现

详见 `rubrics/v0001_draft.md` 和逐篇笔记。现阶段最重要的变化是：
识别不同写作任务；区分引用/复述与作者自己的展开；按整体发展与沟通效果判断，
而非用拼写、段落数量、必须反驳或事实完美作为硬门槛。

主题索引由关键词规则产生，仅用于覆盖检查，可能误分，不是人工题目标签。
字数等统计也只用于审计和寻找反例，不构成字数到分数的固定映射。
